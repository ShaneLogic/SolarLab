# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

1D drift-diffusion + Poisson + mobile-ion simulator for thin-film solar cells (perovskite, CIGS, c-Si), with a FastAPI backend and a Vite/TypeScript/Plotly frontend that wraps the Python experiments as a browser UI.

## Repository Layout

`perovskite_sim/` is the installable Python simulation library, `backend/` the FastAPI wrapper around it, `frontend/` the Vite + TS + Plotly single-page UI, `configs/` the YAML device presets consumed by both CLI and UI, `tests/` the pytest suite, and `notebooks/` exploratory benchmarks.

Every layer talks to the next one through `DeviceStack` + `MaterialParams` (immutable frozen dataclasses); there is no shared mutable state.

## Simulator Architecture (`perovskite_sim/`)

**Evidence wording (2026-08-14 audit).** SCAPS, IonMonger, and Driftfusion
agreements that use fitted contact potentials, de-spike factors, interface
calibration factors, or other disclosed scaffolds are calibrated reproduction
or trend-aligned regression anchors. Historical phrases such as "matched by
physics", "root cause of the gap", or "reproduced" in the notes below do not
promote those lanes to independent no-fit validation. Internal numerical
certification, external-solver validation, and experimental validation remain
separate evidence levels.

**Core method.** Method of Lines: Scharfetter–Gummel finite elements on a tanh-clustered multilayer grid for space; `scipy.integrate.solve_ivp(Radau)` for time. Poisson is a tridiagonal solve with harmonic-mean face permittivity, evaluated once per RHS call (no inner Newton loop). State vector is `y = (n, p, P)` per grid node.

**MaterialArrays cache (hot path).** `solver/mol.py:build_material_arrays(x, stack)` returns an immutable `MaterialArrays` bundle holding every per-node / per-face array the RHS needs (`D_n_face`, `D_p_face`, `eps_r`, `N_A`, `N_D`, `P_ion0`, interface masks, boundary concentrations) plus a pre-factored Poisson operator. Every experiment builds this once per run and threads it through `assemble_rhs`, `run_transient`, `split_step`, `_compute_current`, and `_integrate_step` via the `mat=` kwarg. Rebuilding it per RHS call was the dominant cost before the cache landed — do not reintroduce a code path that calls `build_material_arrays` inside the inner loop. Degradation is the one exception: it rebuilds `mat` only when the absorber-damage state actually changes (`mat_active` in `run_degradation`).

**Poisson LU cache.** `physics/poisson.py:factor_poisson(x, eps_r)` does one LAPACK `dgttrf` call and returns a `PoissonFactor` holding `(dl, d, du, du2, ipiv)`. `solve_poisson_prefactored(fac, rho, phi_left, phi_right)` then runs a single `dgttrs` per call — ~40× faster than the legacy `solve_poisson` path. The factorization only depends on `(x, eps_r)`, which are constant across a transient, so it is cached inside `MaterialArrays.poisson_factor`. Legacy `solve_poisson` is kept as a fallback but is not on any hot path.

**Heterojunctions.** `chi` (electron affinity, eV) and `Eg` (band gap, eV) on each layer set the band offsets. Interface recombination uses per-interface `(v_n, v_p)` surface-recombination velocities carried by `DeviceStack.interfaces`. `stack.interface_defects` is **full-layer-aligned** (parallel to `stack.interfaces`); solver-side consumers must go through `models/device.py:electrical_interface_defects()` (substrate-offset-aware, mirrors `electrical_interfaces`) — indexing the raw tuple with the electrical interface number silently shifts every defect on substrate-prefixed stacks (the 2026-06 E10.1 glass regression).

**Effective-DOS band potentials (2026-06, `DeviceStack.dos_band_potentials`, default ON).** The SG flux drives carriers with `phi_n = φ+χ` / `phi_p = φ+χ+Eg` only; with Boltzmann statistics the heterostructure-correct potentials also carry `V_T·ln(N_C)` / `−V_T·ln(N_V)`. Omitting them imposes a spurious `kT·ln(DOS-ratio)` quasi-Fermi-level step at every DOS-contrast heterojunction — 137 mV on `scaps_mirror_v2` (83 meV at HTL/PVK + 54 meV at PVK/ETL), the root cause of the SolarLab-vs-SCAPS V<sub>oc</sub> gap. The fold is correct transport physics (omitting it is the bug), so it is now the **default**: measured default-transient base V<sub>oc</sub> 1.077 (off) → **1.163 (on) ≈ SCAPS 1.168**; the steady-state Newton driver lands 1.169 (the historical "+36 mV / 1.204 overshoot, disable PR" note is stale — both drivers now agree within ~5 mV of SCAPS). **Disable** it per-config with `dos_band_potentials: false`, or globally for IonMonger parity via the **LEGACY tier — which always forces the fold off** regardless of the flag (the gate at `mol.py:745` ANDs `sim_mode.name != "legacy"`). The legacy force-ON env `SOLARLAB_DOS_BAND=1` still works but is redundant now. When active, `build_material_arrays` folds the corrections into the cached chi/Eg **arrays** (transport + TE see them; ni/n1/p1/boundary densities deliberately untouched), with the absorber layer as reference. Requires per-layer `Nc300`/`Nv300` (populated by `scaps_compat/loader.py` from `N_C_cm3`/`N_V_cm3`, or directly as SI `Nc300`/`Nv300` layer keys in standard YAMLs — `models/config_loader.py` also parses the device-level `dos_band_potentials` and `flat_band_contacts` keys since 2026-06, so non-SCAPS device systems get the corrected transport declaratively); layers without DOS data are skipped, so legacy configs are bit-identical even with the flag on. Tests: `tests/unit/solver/test_dos_band_potentials.py`, `tests/unit/solver/test_interface_defect_alignment.py`.

**Finite-rate outer contacts (renamed contract 2026-08-11; historical flag `DeviceStack.flat_band_contacts`, default OFF).** The flag now has one physical responsibility: it activates the Phase-3.3 Robin carrier path on all four carrier/side channels **regardless of tier** (`S = 1e5 m/s` unless explicit `S_*` fields are set), referenced to the doping-derived contact equilibria. With an explicit `built_in_potential_mode`, it does **not** select the Poisson contact potential. All electrostatic consumers read the independently resolved signed `MaterialArrays.V_bi_bc`; 2D extrudes that same value and `junction_polarity`. The only retained coupling is the compatibility sentinel (`built_in_potential_mode is None`): an old YAML with `V_bi` and `flat_band_contacts: true` continues to use historical `compute_V_bi()` so shipped baselines do not move. Tests: `tests/unit/solver/test_flat_band_contacts.py`, `tests/unit/models/test_built_in_potential_modes.py`. **Robin contacts + the density steady-state driver remain incompatible in the diagnosed near-insulating-contact spike (2026-06-22; won't-fix without the QF engine).** Newton stalls around residual 2.6e3 and its certified transient fallback can diverge to non-finite carrier/potential values even with ions frozen; changing the grid, seed, or ion state did not repair it. Do not reintroduce the old electrostatic coupling as a workaround or retry this as a tolerance fix.

**Interface-formulation campaign — four FALSIFIED attempts, one net-positive. Full measured evidence: `.claude/skills/scaps-interface-formulations/SKILL.md` — read it before re-attempting any of these or proposing a new interface formulation.**

- `interface_two_sided` (default OFF) — measured **exact no-op** on every sweep. Do NOT re-try additive mirror channels.
- `interface_shared_occupancy` (default OFF) — **FALSIFIED**: collapses the CBO trend 734→203 mV. Do NOT re-try occupancy algebra on bulk-node densities; Gaussian E_t integration is pre-falsified by the same probe lineage (bulk-node sampling is E_t-blind by 6–13 orders).
- `interface_plane_closure` (default OFF, env `SOLARLAB_IFACE_PLANE=1`) — the first net-positive formulation (true plane densities from a per-RHS 2×2 flux balance, `physics/interface_plane.py`). Requires the parity configuration (`dos_band_potentials` + reference DOS) and takes precedence over all other interface formulations. The trap-level clamp to the plane gap is load-bearing — without it the CBO arm collapses 734→284 mV.
- SS interface-plane carrier states (`iface_states=True`, calibrated per interface via `InterfaceDefect.iface_state_calibration_factor`) — first formulation to flip the ETL-doping direction. Calibrated HTL/PVK 0.02, PVK/ETL 0.10 on `scaps_mirror_v2`. The residual sweep-magnitude errors are **STRUCTURAL, not a further-tuning target**; three independent falsifications say no density-product rate algebra fixes E_t in this regime.
- `het_recomb_despike` (default 0.0 = OFF; `0.53` on `scaps_mirror_v2`) — the base V_oc gap is bulk **Auger** over-counting a band-offset hole spike, NOT interface recombination.

**Direct steady-state driver (2026-06, `experiments/steady_state.py`) — second structural piece of the parity architecture.** SCAPS is an ion-free steady-state solver, so parity quantities are defined at the ion-free steady state; this driver solves `F(y)=0` on the SAME `assemble_rhs` the transient integrates (one physics, two drivers; ions byte-frozen from the seed). `solve_steady_state` (damped log-space Newton, FD Jacobian, peak-density residual scaling — density-relative rates floor at cancellation noise ~1e6 1/s at dark depletion nodes — dual convergence criteria + J-error-bounded stall acceptance), `run_jv_sweep_ss` (voltage continuation), `solve_voc_ss` (direct J=0 bisection, no grid artifact). Where Newton cannot finish (the V*≈0.858 interface-switch region and the V_oc knee), a **certified transient point-fallback** computes the point (escalating 6.4–100 ms Radau settles, max_step-capped, residual-guarded against the measured chattering attractor at res≈14); clean fallback states keep the continuation un-poisoned. The TE cap gets a **smooth magnitude-min blend** via `MaterialArrays.te_softness` (default 0.0 = bit-identical hard cap; the SS driver sets 0.02 on its own mats only — transient experiments never see it). No silent fallback anywhere: non-convergence raises `SteadyStateError`. **Measured: SS J-V matches the frozen-ion transient within 5 mV V_oc / 1% J_sc; direct V_oc within 2 mV of the sweep.** **Modified-Newton Jacobian/LU reuse (2026-06):** the dominant cost is the dense FD Jacobian (~n_unk full `assemble_rhs` evals per iteration); the Newton loop now reuses the cached `scipy.linalg.lu_factor` across **chord** iterations, rebuilding only on the first iteration, a stale-factor line-search rejection (rebuild + retry before declaring a stall), or heavy backtracking (`lam<0.5`). A freshly built+solved step is **bit-identical** to the original full-Newton `np.linalg.solve` path (the `lu_factor` is just additionally cached); only reused iterations differ, and they converge to the same residual tol — **measured V_oc identical to 5 decimals, ~1.4× faster on warm-started solves** (the bigger SS-harness speedup is the calibrated config being far better-conditioned: a Nd_ETL=1e15 point that took ~705 s uncalibrated solves in ~3 s). Kill-switch env `SOLARLAB_SS_JAC_REUSE=0` forces a fresh Jacobian every iteration (legacy path). **`run_jv_sweep_ss(stop_after_voc=True)` (2026-06, default False = legacy full-`V_max` sweep):** stops the continuation the moment J crosses zero (V_oc bracketed). Continuing past V_oc into deep forward injection (V ≫ V_oc) reaches non-convergent points whose certified transient fallback grinds for minutes — the diagnosed cause of full-FOM SS-sweep hangs when a fixed `V_max` overshoots a sweep point's V_oc (e.g. `V_max=1.35` on a point with V_oc≈1.0). The 0→V_oc arc fully determines V_oc/J_sc/FF/PCE, so for figure/FOM sweeps either set `stop_after_voc=True` (robust at any `V_max`) or bound `V_max ≈ V_oc + margin` — both make full-FOM SS fast (~1-5 s/point) and complete. The interior knee (V*≈0.858) is NOT the bottleneck — it solves in <0.1 s; only V ≫ V_oc grinds. Known limit (documented engine boundary): two deep-tail regimes fail honestly and a Gummel fallback does **not** help. (a) Near-insulating contacts (Nd_ETL ≤ 1e10) find no J=0 crossing below 1.6 V — a physics absence, not a solver miss (the transient agrees; xfail'd gate carries the diagnosis). (b) Deep CBO (ΔE_C ≤ −0.2) is pathological for **any** algebraic Newton: measured at ΔE_C=−1.0, V=0.3 (peak-relative residual, tol 1e-6) the **coupled Newton best 4.2e4 and raises cleanly in 0.6 s**, decoupled Gummel 1e9, **Anderson 3e9**, **PTC (pseudo-transient continuation) 2e8–2e9** — four Newton-family methods, all 10–15 orders above tol; only a long transient damps the stiff modes (plain iface-stripped settle reaches res ~1e-2 in 0.6 s). CBO is a band-offset effect (SS ≈ transient), interface states inactive in the collapsed regime. **The CHI_ETL validation figure now shows the full-range SS curve**: genuine SS-Newton over the flat-band arm (filled) + the SS driver's certified transient fallback over deep-CBO (hollow, = the f=0.53 transient). The dormant `_gummel_point` scaffold + `phi_frozen` seam stay in-tree (env `SOLARLAB_SS_GUMMEL`, bit-identical); **the Gummel/M4 leg is closed won't-fix** (verdict + table: `docs/superpowers/specs/2026-06-22-gummel-ss-solver-scope.md` §0). Tests: `tests/unit/experiments/test_steady_state.py`.

**Built-in-potential source contract (2026-08-11).** New configurations select one of three explicit modes. `semiconductor_work_function` evaluates each outer electrical layer at its physical contact face using positive `chi`, `Eg`, `Nc300`, `Nv300`, charge-neutrality doping, active-tier temperature/DOS scaling, optional Varshni shift, and enabled grading; it fails closed if those inputs are missing. `metal_work_function` requires positive `work_function_left_eV` and `work_function_right_eV`. Both return the signed contact potential `φ(right)-φ(left) = W_left-W_right`. `legacy_manual` consumes the positive `V_bi_override` magnitude and takes orientation from the historical endpoint estimate. `built_in_potential_mode=None` is not a public fourth mode: it is the old-YAML compatibility sentinel, preserving manual `V_bi` and the former `flat_band_contacts -> compute_V_bi()` implication. The deprecated `compute_V_bi()` implementation remains unchanged for that compatibility path; the strict DOS/T implementation is `compute_semiconductor_V_bi()`. `poisson_built_in_potential()` feeds `MaterialArrays.V_bi_bc`; `operating_built_in_potential()` feeds J-V/degradation/TPV/Suns-Voc defaults and preserves the historical `V_bi_eff` only for compatibility stacks. `junction_polarity` maps positive `V_app` to a reduction in `|V_bi_bc|` for either orientation and must not be removed or wrapped into an unconditional `abs()`. The 2D material builder reuses the resolved 1D value and polarity. `config_loader.built_in_potential_fields_from_device_dict` is shared by file, SCAPS-shape, and inline backend loading; `_stack_to_config_dict` and the frontend editor preserve an old payload until the user deliberately changes its selector. Tests: `tests/unit/models/test_built_in_potential_modes.py`, `tests/unit/backend/test_built_in_potential_config.py`, `frontend/src/config-editor-built-in-potential.test.ts`. **Thermionic emission (TE) at heterointerfaces.** At interfaces where the conduction-band offset |delta_Ec| or valence-band offset |delta_Ev| exceeds 0.05 eV, the SG flux is capped to the Richardson-Dushman thermionic emission limit (`fe_operators.thermionic_emission_flux`). This prevents the SG scheme from overestimating current across sharp band discontinuities (a known artifact when the band offset is resolved in a single grid spacing). The capping is applied in `continuity.py:carrier_continuity_rhs`. Richardson constants `A_star_n` and `A_star_p` default to the free-electron value (1.2017e6 A/(m²·K²)) and can be overridden per layer in YAML configs. Interface faces where TE activates are pre-computed in `MaterialArrays.interface_faces`. Note: IonMonger does not use TE, so our V<sub>oc</sub> is ~0.1 V higher than IonMonger's on the same parameter set; Phase 5 (tiered modes) will add a legacy mode that disables TE for exact IonMonger reproduction.

**Transfer-matrix optics (TMM).** `physics/optics.py` implements the coherent thin-film transfer-matrix method (Pettersson et al. 1999 / Burkhard et al. 2010) for position-resolved optical generation G(x). Each layer carries `optical_material` (string key for n,k CSV data in `perovskite_sim/data/nk/`) or `n_optical` (constant refractive index fallback). When any layer has `optical_material` set, `mol.py:_compute_tmm_generation` builds the TMM stack, loads the AM1.5G spectrum from `data/am15g.csv`, and computes G(x) once during `build_material_arrays`. The result is stored as `MaterialArrays.G_optical` and used in `assemble_rhs` instead of Beer-Lambert. Key physics: the absorption formula includes the `n_real / n_ambient` Poynting-vector correction so that R+T+A=1 (energy conservation). Without `optical_material`, the original Beer-Lambert `G = alpha * Phi * exp(-alpha*x)` path is unchanged. The `_inv2x2` batched matrix inverse in `optics.py` has a determinant guard (clamps `|det| < 1e-30` to avoid division by zero at wavelengths where the transfer matrix is singular); do not remove this guard.

**Activated presets:** `nip_MAPbI3_tmm.yaml`, `pin_MAPbI3_tmm.yaml` (Phase 2 — Apr 2026). Both prepend a 1 mm `role: substrate` glass layer (optical-only) and set `optical_material` on every electrical layer. The vanilla `nip_MAPbI3.yaml` and `pin_MAPbI3.yaml` remain Beer-Lambert for back-compat with existing benchmarks. Substrate layers are filtered out of the drift-diffusion grid by `electrical_layers()` in `models/device.py`; the TMM spatial grid is offset by the substrate cumulative thickness so G(x) lands on the correct electrical nodes.

**Photon recycling / detailed-balance radiative recombination (Phase 3.1 — Apr 2026).** When `SimulationMode.use_photon_recycling` is True and TMM optics are active, `build_material_arrays` scales the absorber `B_rad` by the Yablonovitch single-pass escape probability `P_esc = min(1, 1/(4·n²·α·d))`, where `α(λ_gap) = 4πk(λ_gap)/λ_gap` is the intrinsic absorption at the band edge and `n` is the real index at the same wavelength (both read from the TMM layer's n,k arrays at `λ_gap = hc/Eg`). The factor is applied per absorber layer using the role tag, so only layers marked `role: absorber` get rescaled — transport layers are untouched. Implementation lives in `physics/photon_recycling.py` (`compute_p_esc`, `compute_p_esc_for_absorber`, `wavelength_at_gap`). The flag is on in both FAST and FULL, off in LEGACY. Comparing PR on vs off is only apples-to-apples when TMM is on in both runs (G(x) must be bit-identical); the regression test `tests/regression/test_photon_recycling_voc.py` does this by `monkeypatch`-ing `resolve_mode` on both `models.mode` and `solver.mol` before each V<sub>oc</sub> measurement. The `radiative_limit.yaml` preset (absorber τ → 1 s, Auger = 0, detailed-balance `B_rad = 4e-17`) is the canonical test vector and produces a ~78 mV V<sub>oc</sub> boost with PR on, inside the literature window for MAPbI3. The reciprocal emission leg — adding the reabsorbed fraction back into G(x) self-consistently — landed as Phase 3.1b (see below); when `use_radiative_reabsorption` is on, the build-time `B_rad *= P_esc` scaling is skipped and the suppression is delivered per-RHS instead, which is bit-equivalent at V<sub>oc</sub> but more accurate when n·p is non-uniform.

**Self-consistent radiative reabsorption (Phase 3.1b — Apr 2026).** Closes the photon-recycling loop opened in Phase 3.1. When `SimulationMode.use_radiative_reabsorption` is True (FULL only — FAST keeps the cheaper Phase 3.1 build-time scaling), `build_material_arrays` does **not** apply the `B_rad *= P_esc` collapse; instead, for every absorber layer with `Eg > 0` it caches a `(mask, P_esc, thickness)` tuple on `MaterialArrays.absorber_masks / absorber_p_esc / absorber_thicknesses` and sets `has_radiative_reabsorption = True`. On every RHS call `assemble_rhs` then computes per absorber `R_tot = ∫ B_rad · n · p dx` over the cached mask and adds the reabsorbed fraction `G_rad = R_tot · (1 − P_esc) / thickness` uniformly back onto the absorber's `G` nodes. Net effect: the bulk `B_rad` on the cache stays at its intrinsic value, full radiative emission acts as a sink in `carrier_continuity_rhs`, and the Yablonovitch-trapped fraction acts as a uniform source. In the spatially-uniform n·p limit (which is exactly what `V_oc` looks like in the bulk because the quasi-Fermi splittings are flat away from the contacts) this reproduces the Phase 3.1 V<sub>oc</sub> boost to within sub-mV — the equivalence pinned by `tests/regression/test_radiative_reabsorption.py::test_radiative_reabsorption_matches_phase_3_1_at_voc`. Where 3.1b differs is the non-uniform regime: under strong injection, near the contacts, or in tandem sub-cells with engineered absorber profiles, emission near a high-`n·p` region can feed generation in a low-`n·p` region, redistributing carriers in a way the build-time scaling cannot capture. Like Phase 3.2 and 3.3 this hook intentionally breaks the "G computed once at build time" invariant — but only on absorber nodes where `has_radiative_reabsorption` is True, so the cost is bounded. `assemble_rhs` always copies `G` before adding the source so `mat.G_optical` stays read-only across RHS calls. The flag is gated under `use_photon_recycling`: turning radiative reabsorption on without photon recycling is a no-op (no `P_esc` was ever computed). The backend label appends `· PR reabsorption` when active, distinguishing FULL from FAST in the SSE result payload (`backend/main.py:_describe_active_physics`).

**Field-dependent mobility (Phase 3.2 — Apr 2026).** When `SimulationMode.use_field_dependent_mobility` is True and at least one layer sets a nonzero `v_sat_{n,p}` or `pf_gamma_{n,p}`, `assemble_rhs` recomputes effective per-face diffusion coefficients on every RHS call from the Poisson-solved face field `E_face = -∂φ/∂x`. Two empirical models compose multiplicatively: Poole-Frenkel `μ_PF(E) = μ₀ · exp(γ_PF · √|E|)` (field-assisted hopping in disordered / organic HTLs — γ ~ 3e-4 (V/m)^-0.5 typical for spiro-OMeTAD) followed by Caughey-Thomas `μ_CT(E) = μ · (1 + (μ·|E|/v_sat)^β)^(-1/β)` (velocity-saturation cap — β = 2 is the Canali form for silicon electrons, β = 1 is the Thornber form for silicon holes; v_sat ~ 1e5 m/s is perovskite-realistic). Both primitives live in `physics/field_mobility.py` (`caughey_thomas`, `poole_frenkel`, `apply_field_mobility`). **Critically, this is the first physics path that intentionally breaks the "build once, reuse" invariant of `MaterialArrays`** — μ(E) depends on state, so `D_n_face` / `D_p_face` are recomputed per RHS call rather than cached. The hook is opt-in per layer: v_sat = 0 and γ_PF = 0 (the defaults) leave μ untouched at that face, and `MaterialArrays.has_field_mobility = False` when no layer opts in — in which case the hot path is skipped entirely and results are bit-identical to Phase 3.1. `jv_sweep.compute_current_components` applies the same per-face correction to its terminal J<sub>n</sub> / J<sub>p</sub> calculation so charge conservation at the contacts is preserved. The integration test `tests/integration/test_field_mobility_integration.py` exercises the ON path (default presets leave it OFF; injecting v_sat perturbs the full J-V curve measurably without any NaN/Inf).

**Tiered simulation modes (Phase 5 — Apr 2026).** Every Phase 1–3 physics upgrade is gated on a flag in `SimulationMode` (defined in `perovskite_sim/models/mode.py`). The three named tiers — `LEGACY`, `FAST`, `FULL` — bundle the nine flags into useful combinations so that callers can pick a fidelity / speed trade-off without editing individual flags. The tier acts as a **ceiling**: turning a flag on only enables the corresponding hook if the config actually provides the parameter the hook needs (TMM needs `optical_material`, TE needs non-zero `chi` and `Eg` with a real interface offset, selective contacts need at least one `S_*`, field-mobility needs `v_sat_{n,p}` or `pf_gamma_{n,p}`, radiative reabsorption needs `use_photon_recycling` plus an absorber with `Eg > 0` under TMM, etc.). This "enable-if-configured" pattern means the tier strings are safe to set on every preset — flags are silent when inactive rather than forcing physics that the stack cannot support. Flag matrix: **LEGACY** turns everything off for IonMonger reproducibility. **FAST** turns on every *build-once* upgrade (TE, TMM, dual ions, trap profile, T-scaling, photon recycling) but keeps the three *per-RHS* upgrades off — radiative reabsorption (3.1b), field-dependent mobility (3.2), and selective contacts (3.3) all break the MaterialArrays build-once invariant, so FAST tier skips them. **FULL** turns everything on, including the three per-RHS hooks. A YAML preset can pin a tier with a top-level `device.mode: legacy|fast|full`; `DeviceStack.mode` defaults to `"full"` so any config that does not pin a mode gets the full physics set. `resolve_mode` (in `models/mode.py`) is idempotent on `SimulationMode` instances, parses strings case-insensitively, and returns `FULL` for `None`. The backend renders the resolved tier into the SSE result payload via `_describe_active_physics`, which produces strings like `"FULL  band offsets · TE · TMM · dual ions · trap profile · T-scaling · photon recycling · PR reabsorption · μ(E) · Robin contacts"` — the per-RHS fragments only appear when the corresponding flag is on, so FAST and LEGACY get a shorter label. The tier system is invariant-tested in `tests/unit/models/test_mode.py` (flag monotonicity: `LEGACY ⊆ FAST ⊆ FULL`), and end-to-end in `tests/regression/test_tier_regression.py` (LEGACY reproduces FAST/FULL on a plain preset; FAST ignores per-RHS opt-ins even when the config provides them; LEGACY disables TE even with band offsets configured; YAML `mode:` round-trips through the full loader).

**Selective / Schottky outer contacts (Phase 3.3 — Apr 2026).** The pre-3.3 outer boundary treatment was a hard Dirichlet pin: at nodes 0 and N-1 the carrier densities were clamped to their ohmic-equilibrium values (`mat.n_L`, `mat.n_R`, `mat.p_L`, `mat.p_R`) and `dn` / `dp` at those indices were zeroed so the solver never touched them. This is the correct limit for an ideal ohmic contact but cannot represent a selective (electron- or hole-blocking) or Schottky-barrier contact, which are the dominant outer-contact types in real perovskite devices. When `SimulationMode.use_selective_contacts` is True and `DeviceStack` supplies at least one of `S_n_left`, `S_p_left`, `S_n_right`, `S_p_right` (in m/s), `build_material_arrays` sets `has_selective_contacts = True` and the four `S` values propagate onto `MaterialArrays`. `assemble_rhs` then (a) keeps the boundary density for that carrier/side from the integrated state vector rather than overriding it, (b) computes a Robin-type flux `J = ±q · S · (density − density_eq)` via `physics/contacts.selective_contact_flux`, and (c) plumbs that flux through `carrier_continuity_rhs` as an extra `J_n_L` / `J_n_R` / `J_p_L` / `J_p_R` entry in `params`, which replaces the zero-flux pad at that boundary and skips the `dn[0]=0` / `dn[-1]=0` pin for that specific carrier. Sides left as `None` (the default, and what every shipped preset supplies) keep the exact pre-3.3 Dirichlet behaviour, so the feature is backward-compatible at the numerics level. `S → ∞` recovers the ohmic limit; `S = 0` is a perfectly blocking (Neumann) contact; finite S allows the boundary node to evolve with a Robin time constant `~ dx_cell / S`. YAML accepts both a nested `device.contacts: { left: {S_n, S_p}, right: {S_n, S_p} }` block (preferred) and flat top-level `device.S_n_left` etc. keys. `experiments/jv_sweep._state_fields`, `solver/mol.split_step`, and the sign-aware `dn[boundary] = 0` overwrites in `assemble_rhs` all respect the Robin/Dirichlet split per carrier / per side. Schottky helpers `schottky_equilibrium_n(N_c, φ_B, V_T)` and `schottky_equilibrium_p(N_v, φ_B, V_T)` live alongside the Robin primitives in `physics/contacts.py` — these compute the thermionic equilibrium density at a barrier and are intended as the source of the `n_eq` argument to `selective_contact_flux` when the user wants a Schottky rather than ohmic-equilibrium reference. The `configs/selective_contacts_demo.yaml` preset exercises the full path on the nip MAPbI3 stack (small wrong-sign S, moderate matched-carrier S) and the integration test `tests/integration/test_selective_contacts_integration.py` covers the activation flag, YAML round-trip, finite-RHS under aggressive Robin fluxes including the `S=0` Neumann limit, and a J-V smoke test that fails if the Robin hook is silently bypassed.

**Temperature-dependent radiative rate and bandgap (Phase 4b — Apr 2026).** Extends the Phase 4 temperature-scaling hook (`SimulationMode.use_temperature_scaling`, gated via FAST/FULL, off in LEGACY) to cover two more parameters that matter at non-300 K: the band-to-band radiative coefficient `B_rad` and the optical bandgap `Eg`. Both are opt-in via new `MaterialParams` fields so pre-Phase-4b configs are bit-identical. `B_rad_at_T(B_300, T, gamma)` implements the empirical power law `B(T) = B_300 · (T/300)^γ` with `γ = 0` as the opt-out default (literature typical for MAPbI3 is `γ ≈ -1.5`, the Varshni-free detailed-balance scaling for a non-degenerate semiconductor at fixed bandgap); setting `MaterialParams.B_rad_T_gamma` to a non-zero value activates the scaling in `build_material_arrays` on every per-layer `B_rad` write. `eg_at_T(Eg_300, T, alpha, beta)` implements the Varshni bandgap shift **referenced to 300 K** (rather than the classical Varshni-to-0-K form), so `MaterialParams.Eg` continues to mean "the bandgap at 300 K" and the shift is applied only when `varshni_alpha ≠ 0`: `Eg(T) = Eg_300 − α·[T²/(T+β) − T_REF²/(T_REF+β)]`. Silicon uses `α ≈ 4.73e-4 eV/K, β ≈ 636 K` (heating narrows Eg); MAPbI3 is opposite — Eg *widens* with heating, reproduced by `α ≈ −3e-4 eV/K, β ≈ +200 K`. The Varshni-shifted `Eg_T` is fed **both** to `chi[mask]`/`Eg[mask]` (so downstream thermionic emission, band offsets, and photon recycling see the shifted band edges) **and** to `ni_at_T` (so `ni²(T) ∝ exp(−Eg(T)/kT)` is self-consistent with the shifted bandgap). The degenerate case `T + β = 0` returns `Eg_300` rather than dividing by zero. Both hooks respect the LEGACY gate — if `sim_mode.use_temperature_scaling` is off, `B_rad` and `Eg` stay at their 300 K values even when the new fields are populated (pinned by the `test_legacy_mode_*` tests in `tests/unit/solver/test_temperature_scaling_plumbing.py`). The full test surface is 14 unit tests in `tests/unit/physics/test_temperature.py` (identity-at-300 K, power-law exponent, zero-input sentinels, default-gamma-is-zero, Varshni sign checks for silicon vs MAPbI3 parameter sets, degenerate-denominator guard) plus 7 plumbing tests in `tests/unit/solver/test_temperature_scaling_plumbing.py` (default leaves arrays unchanged, opt-in scales correctly, legacy-mode freezes at 300 K, shipped configs remain bit-identical to the pre-Phase-4b build path). Phase 4b does not add a new tier flag — it reuses the existing `use_temperature_scaling` gate, which keeps LEGACY bit-identical to IonMonger even when a preset carelessly sets `B_rad_T_gamma` or `varshni_alpha`.

**Position-dependent trap profiles (Phase 4a — Apr 2026).** The bulk SRH lifetime on each layer represents the cleanest part of the film; in real perovskite devices grain-boundary defects concentrate near each transport-layer interface and the local SRH lifetime drops accordingly. Phase 4a turns the original inline Phase 4 profile into a reusable physics module and adds a second shape for defect layers with a well-defined finite extent. The primitives live in `physics/traps.py`: `exponential_edge_profile(x_local, thickness, N_t_interface, N_t_bulk, L_d)` returns `N_t(x) = N_t_bulk + (N_t_interface − N_t_bulk) · (e^{−x/L_d} + e^{−(d−x)/L_d}) / S_max` (two exponentials added rather than maxed so overlapping decay tails blend instead of double-counting one side, then divided by the analytic supremum `S_max` so the profile saturates AT `N_t_interface` — the un-normalized Phase 4 form overshot by up to 2×, see the 2026-07-26 review round 2 section below); `gaussian_edge_profile(...)` returns the same construction with `G(s) = exp(−(s/sigma)²)` and falls off faster in the tail (`~1e-4` at 3σ vs `~0.05` at 3·L_d for the exponential) — useful when the interface defect slab has a measured finite thickness rather than a long tail; `tau_from_trap_density(tau_bulk, N_t, N_t_bulk)` applies the SRH inverse-density rule `tau(x) = tau_bulk · N_t_bulk / N_t(x)` with the denominator floored at `N_t_bulk` so that `N_t_interface < N_t_bulk` (a passivation profile) still yields a physical, monotone correction; `has_trap_profile_params(params)` is the presence check used by `build_material_arrays` to decide whether to call the profile. Shape selection is per-layer via the new `MaterialParams.trap_profile_shape` field (`"exponential"` default | `"gaussian"`), wired through `config_loader.py` as `layer_cfg.get("trap_profile_shape", "exponential")`. `L_d = 0` or `sigma = 0` are degenerate "no profile" sentinels that return `N_t_bulk` everywhere, and `L_d = 0` on a layer that still opts in simply leaves `tau` at its layer-uniform bulk value. `build_material_arrays` also caches the per-node trap density on `MaterialArrays.N_t_node` (zeros on nodes that belong to a layer with no trap params, `N_t_bulk` on layers that only specify the bulk density without a profile, and the full `N_t(x)` on layers that opt in), plus a boolean `has_trap_profile` that reports whether at least one layer triggered the profile. These diagnostics let downstream hooks (interface SRH, band-tail absorption, mobility degradation) reuse the same `N_t(x)` without recomputing the profile. The whole module is gated by `SimulationMode.use_trap_profile` (on in FAST and FULL, off in LEGACY); when the flag is off `build_material_arrays` skips the profile entirely and `N_t_node` reflects the uniform-bulk fallback. Unit tests in `tests/unit/physics/test_traps.py` pin the endpoint formula, midpoint bulk recovery, monotonic decay into the interior, Gaussian tail decays faster than exponential at ~3·L, zero-length sentinel yields flat bulk, `tau_from_trap_density` passivation floor, and the `has_trap_profile_params` presence check. The existing integration test `tests/integration/test_temperature_trap.py` continues to cover the end-to-end `build_material_arrays` path (now through the refactored module) without modification.

**Continuous bandgap grading (2026-06, `DeviceStack.band_grading`, default OFF, env `SOLARLAB_BAND_GRADING=1`).** SCAPS "material-driven" grading (Burgelman & Marlein, 23rd EU PVSEC 2008): a graded layer is a mix of two pure materials A (front face, the existing scalar `chi`/`Eg`) and B (back face, the new `Eg_back`/`chi_back`), with composition `y(x)` across the thickness. `physics/grading.py` holds the pure functions: `grading_coordinate` (`y(x)`: linear / parabolic / exponential-notch Burgelman Eq.6, with `grading_direction` flip), `band_gap_profile` (`Eg(y) = (1-y)·Eg_A + y·Eg_B − b·y(1-y)`, bowing `grading_bowing`), `affinity_profile` (Vegard linear `chi(y)`), and the **front-anchored** Eg-derived terms `grade_ni_sq` (`ni²(x) = ni_front²·exp(−(Eg(x)−Eg_front)/V_T)` — the `ni²=Nc·Nv·exp(−Eg/kT)` ratio with the DOS factors cancelled, so no per-layer DOS is needed) and `grade_n1_p1` (`r = exp(−ΔEg/2V_T)` on both, preserving `n1·p1 = ni²(x)` per node). A layer is graded iff `has_grading_params(p)` (`Eg_back` or `chi_back` set). `build_material_arrays` fills the per-node `chi`/`Eg`/`ni_sq`/`n1`/`p1` arrays from these at build time (the gate `_band_grading` ANDs the device flag/env with `sim_mode.name != "legacy"`), replacing the scalar broadcast at `mol.py:646-647`/`659-665`; the DOS-fold and TE interface faces compose on top unchanged. This is a **static** (per-build) transform threaded through the immutable `MaterialArrays` — never on the per-RHS path, so it carries **no Newton-contraction risk** (unlike the dropped per-RHS BBD interface-density term). CB/VB split is controlled by grading `chi` and `Eg` independently (`E_C = −chi`, `E_V = −chi−Eg`): grade `chi_back < chi_front` for an electron back-surface field. **Bit-identical contract** (three gates): every new `MaterialParams` field defaults None/sentinel (→ `has_grading_params` False → scalar branches run unchanged); `band_grading` defaults False; LEGACY forces off. A *flat* grade (endpoints equal, bowing 0) is byte-identical because `band_gap_profile`/`affinity_profile` short-circuit to a constant-front array, so `grade_ni_sq`/`grade_n1_p1` see `exp(0)=1` exactly — pinned by `tests/unit/solver/test_band_grading_plumbing.py` (`np.array_equal` vs flag-off + LEGACY force-off). **Photon-recycling** `λ_gap` uses the narrowest (front/back) endpoint gap for a graded absorber (`mol.py` PR block), gated on `has_grading_params` so a Varshni-T-shifted *ungraded* absorber is untouched. **Contact V_bi**: `compute_V_bi`'s `_edge_params` (`models/device.py`) drives a graded outer layer's contact from its back-face endpoints (ungraded → identical object → identical float). **Mesh**: a graded layer's intervals are refined by its `grading_N_mult` via the shared `jv_sweep._layer_node_counts` helper (both grid sites read it, so non-graded sizing is byte-identical) — bump it for steep exponential notches (a large single-cell ΔEg lands on one over-injecting face; interior graded faces are deliberately NOT TE-capped — the band-corrected SG flux is the correct treatment). **Documented limitation**: `alpha`/external TMM n,k are NOT graded — a graded absorber's absorption edge does not shift spatially (SCAPS grades `alpha(λ,y)`); J_sc reflects the uniform-optics electrical effect only. Auger `C_n`/`C_p` stay material constants (only n,p in the rate vary). Demo preset `configs/cigs_graded_notch.yaml` (Ga-rich back-graded CIGS). Tests: `tests/unit/physics/test_grading.py`, `tests/unit/solver/test_band_grading_plumbing.py`, `tests/regression/test_grading_cigs_notch.py` (slow). 1D-scoped (the 2D extrusion would carry the graded arrays but is not covered by the Stage-A 2D parity gate).

**Interface thermionic-field-emission tunnelling (2026-06, `DeviceStack.interface_tunneling`, default OFF, env `SOLARLAB_IFACE_TUNNEL=1`).** SolarLab's TE cap is pure over-the-barrier Richardson-Dushman; SCAPS additionally exposes an intra-band tunnelling channel through a CB/VB spike. `physics/tunneling.py:tfe_gamma` supplies a **static** Padovani-Stratton enhancement `Γ = exp(δ_tun/V_T) ≥ 1` (`E_00 = (q·ħ/2)·√(N_iface/(m*·ε_s))`, `E_0 = E_00·coth(E_00/V_T)`, `δ_tun = |ΔE|·(1 − V_T/E_0)` clamped to `[0, |ΔE|)`). `build_material_arrays` folds it into the per-face Richardson constants at the TE-capped faces (`A*_eff = Γ·A*`) — right after `interface_face_list` is built, using the SAME (graded + DOS-folded) `chi`/`Eg` the TE cap reads. **Why it's safe**: (1) the SAME Γ scales BOTH legs of `thermionic_emission_flux`, so equilibrium `J_TE = 0` is preserved to machine precision (Γ-invariant — pinned by `test_tunneling.py::test_detailed_balance_invariant_under_gamma`); (2) `A_star_*` is consumed ONLY at interface faces (`continuity.py:183/193`), so the fold is **byte-identical on the apply side** — zero per-RHS-path change; (3) the existing `_cap` blends `J_TE` toward the SG flux, so the **SG flux stays the structural ceiling** (Γ lifts TE toward SG, never above); (4) it is **static** (build-time, no live field) → cannot perturb the Newton/Radau contraction (unlike a per-RHS field-dependent term — the dropped BBD class). `N_iface` is the **lighter-doped** adjacent layer (depletion side); `tunnel_mass_eff` (device-level, default 0.2·m_e) is the one free knob. **Documented boundary**: an *intrinsic*-absorber interface (depletion-side doping ≈ 0) gives `E_00 → 0 ⇒ Γ → 1` (little enhancement) — the static doping form captures the base absolute + the doping-direction trend, NOT the field/bias flattening of the spike under forward bias (that needs the deferred per-RHS `E_00(F)` form, which must NOT be promoted without the full clamp/frozen-fallback kit — see the design at `tasks/wtwrzoz92.output`). Requires TE on (the cap face set is only built then); LEGACY forces TE off → tunnelling off by construction. Default OFF = bit-identical (pinned by `tests/unit/solver/test_interface_tunneling.py`). 1D-scoped (the 2D extrusion carries the folded A* but is not covered by the Stage-A gate). Tests: `tests/unit/physics/test_tunneling.py`, `tests/unit/solver/test_interface_tunneling.py`.

**Experiments** (`perovskite_sim/experiments/`):
- `jv_sweep.run_jv_sweep` — forward then reverse scan; reuses the previous steady state as initial condition so ionic memory is preserved and the hysteresis loop comes out of the physics, not post-processing. A per-step `_JV_RADAU_MAX_NFEV = 100_000` guard aborts any single voltage step that consumes too many RHS evaluations (prevents the solver from hanging on pathological substrate-stack configs). Supports `illuminated=False` for dark J-V (G=0, dark-equilibrium start) and `save_snapshots=True` for collecting `SpatialSnapshot` at every voltage point.
- `jv_sweep.compute_current_components` — decomposes the terminal current into J<sub>n</sub> (electron), J<sub>p</sub> (hole), J_ion (ionic, both species), and J_disp (displacement) at every mesh face. Uses the same SG flux formulas as `assemble_rhs` but multiplied by Q for A/m² units. Ion current includes the steric Blakemore correction and dual-ion support.
- `jv_sweep.extract_spatial_snapshot` — extracts a `SpatialSnapshot` (phi, E, n, p, P, rho) from a packed state vector at a given voltage. Used internally by `save_snapshots` and available as a standalone API.
- `band_diagram.compute_band_diagram(stack, V_app, *, illuminated=True, N_grid=80, settle_t=1e-2)` — the SCAPS Energy-Bands-Panel equivalent: returns a frozen `BandDiagram(x, E_C, E_V, E_Fn, E_Fp, V_app)` (all eV) at a chosen bias. **The state is settled to steady state first** (illuminated: `solve_illuminated_ss`; dark: `solve_equilibrium` then an escalating dark transient to the true zero-current state — the raw `solve_equilibrium` seed has J≠0), so the quasi-Fermi levels are physically meaningful: flat and coincident at equilibrium, split by ~qV under bias (pinned by `tests/unit/experiments/test_band_diagram.py`: eq E_F flat <150 mV; absorber E_Fn−E_Fp = qV). Band edges use the **physical** per-layer `chi`/`Eg`/`Nc300`/`Nv300` (NOT the DOS-folded transport arrays); with the effective-DOS fold active this makes `E_Fn = −φ−χ+V_T ln(n/N_C)` flat at equilibrium. E_Fn/E_Fp are **NaN-masked** in deep-minority regions (`n/N_C < 1e-16`) where the level is numerically ill-defined (e.g. electrons at the HTL contact). Raises `ValueError` if the config lacks `Nc300`/`Nv300`. Data-only (no plotting in core, like `SpatialSnapshot`).
- `jv_sweep.compute_metrics(V, J, *, assume_jsc_positive=True, V_oc_max=None)` — central V<sub>oc</sub> / J<sub>sc</sub> / FF / PCE extractor. **V_oc is taken where |J| first REACHES the resolution floor `_J_ZERO_FRACTION_OF_JSC · |J_sc|` (1e-3), not at the first sign CHANGE (2026-07-28).** Past flat band the photocurrent on some stacks collapses to ~1e-5 of J_sc, and in that regime the *sign* of J is numerical noise: the sign-change rule made the same device report 1.44 / 2.42 / 2.68 V or "unbracketed" depending only on `V_max` and the sampling, and which test failed even changed between a full-suite and a single-file run (diagnosed on `scaps_mirror` + low-N_D ETL, where `D_ion = 0` in every layer — this was never ion history). `V_oc_max` is an optional hard ceiling; `run_jv_sweep` passes `thermodynamic_voc_ceiling(stack)` = `min(Eg)` over electrical layers, so a V_oc above the band gap is refused as unbracketed rather than reported. Measured **exactly inert on healthy devices** (all deltas 0.00e+00) — it only fires where the old answer was already noise. Caveat recorded in the source: the ceiling is `min(Eg)`, so a future stack with a genuinely narrow-gap transport layer would get a ceiling TIGHTER than the thermodynamic bound; `test_voc_collapsed_current.py::test_ceiling_equals_the_absorber_gap_on_every_shipped_preset` is the tripwire. Returns a frozen `JVMetrics(V_oc, J_sc, FF, PCE, voc_bracketed)`. `voc_bracketed=True` when the sweep contains a true zero-current crossing (V<sub>oc</sub> found by linear interpolation between the two adjacent samples whose J flip sign); `voc_bracketed=False` when no crossing exists in the sample range — in which case `V_oc`, `FF`, and `PCE` are zeroed sentinels and only `J_sc` is physically meaningful. The `assume_jsc_positive` kwarg controls the internal sign convention so the helper itself is the single source of truth: 1D `run_jv_sweep` and the Phase-2 / Suns-V<sub>oc</sub> paths leave the default `True` (their J at V=0 is positive); 2D `run_jv_sweep_2d` and `run_voc_grain_sweep` pass `False` so the helper flips J internally rather than asking each call site to sprinkle `J = -J` guards (the 2D Scharfetter-Gummel sign convention has J<0 at V=0). The `voc_bracketed` flag is what the workstation 2D pane reads to render `—` for V<sub>oc</sub> / FF / PCE and an inline `V_oc not bracketed — increase V_max` warning when the sweep window is too narrow; existing 1D callers see no behavioural change.
- `impedance.run_impedance` — defaults to the general transient AC-cycle/lock-in path and adds `ε₀·ε_r·∂E/∂t`. The explicit `method="quasi_fermi_frequency"` path instead linearizes storage, rate, conduction current, and displacement about a residual-certified QF operating point, solves the balanced complex operator with LAPACK refinement, and reports all-face admittance continuity. That path is restricted to the audited local ion-free QF capability envelope and requires `0 < delta_V < 20 mV`; unsupported ions, contacts, interfaces, and non-local physics fail closed.
- `degradation.run_degradation` — long-time transient; at each probe time it takes a **frozen-ion snapshot**: a `replace`-d copy of the stack with `D_ion = 0` in every layer is used for a short settle integration at each probe voltage (`_freeze_ions` + `_measure_snapshot_metrics`). This measures the instantaneous electronic response under the current ionic configuration and is the only correct way to compute snapshot J–V without averaging over ion drift.
- `tpv.run_tpv` — transient photovoltage experiment. Equilibrates at V<sub>oc</sub> under illumination, applies a fractional generation pulse (delta_G_frac), tracks J(t) at fixed V<sub>app</sub>=V<sub>oc</sub>, converts to V(t) via the small-signal relation delta_V = -J * R_oc, and fits a mono-exponential decay time tau. Returns a `TPVResult` with t, V, J arrays plus V<sub>oc</sub>, tau, delta_V0.
- `tandem_jv.run_tandem_jv` — 2T monolithic tandem driver. Runs a combined TMM over the full stack (`physics/tandem_optics.py`) to partition G(x) into top/bottom sub-cell profiles, then performs independent drift-diffusion J–V sweeps with `fixed_generation`, and series-matches at a common current grid (`series_match_jv`). Returns a `TandemJVResult` holding per-sub-cell results plus the tandem J–V curve.

**Tandem optics** (`physics/tandem_optics.py`): Runs one TMM over the entire tandem stack (top + junction + bottom), then splits absorption by layer. Junction layers count as parasitic absorption. The `TandemGeneration` dataclass holds `G_top(x)` and `G_bot(x)` arrays. The tandem config model lives in `models/tandem_config.py` (`TandemConfig`, `JunctionLayer`).

**2D extension — Stage A lateral-uniform parity (Phase 6 — Apr 2026).** Lives in `perovskite_sim/twod/` as a parallel sub-package — it does not touch the 1D solver hot path. The 2D state is `(n(y, x), p(y, x))` only; ions are held as a static Poisson background (`P_ion_static_1d`) extruded from the 1D illuminated steady state, so Stage A has no ionic memory across voltage steps. Grid: `build_grid_2d` produces a tensor-product grid with the existing tanh-clustered y-axis (one `Layer(thickness, Ny_per_layer)` per electrical layer) and a uniform x-axis of `Nx + 1` nodes spanning `lateral_length`. Poisson: `physics/poisson_2d.py` assembles a sparse 5-point stencil with harmonic-mean face permittivity and `scipy.sparse.linalg.splu` factor cached on `MaterialArrays2D` — the same signed Dirichlet contacts as 1D (`phi[0,:]=0`, `phi[-1,:]=V_bi_bc - junction_polarity*V_app`) and lateral periodic or Neumann BCs. The 2D builder reuses `mat1d.V_bi_bc` and `mat1d.junction_polarity`, so explicit metal/semiconductor modes and old compatibility presets cannot diverge between dimensions. The Poisson RHS includes the frozen-ion term `Q*(P_ion_static - P_ion0_2d)`, which is critical for matching 1D's $\rho$ — without it the 2D $\varphi$ diverges at heterointerfaces and SG fluxes blow up. Continuity: `twod/flux_2d.py` implements vectorised 2D Scharfetter-Gummel for both directions with **harmonic-mean face-D** averaging (matches 1D `MaterialArrays.D_n_face`); the SG flux uses `phi_n = phi + chi`, `phi_p = phi + chi + Eg` so band offsets are preserved at heterointerfaces. Thermionic-emission capping: `twod/continuity_2d.py` caps `Jy_n` / `Jy_p` at vertical heterointerfaces (where `|delta_Ec| > 0.05` eV or `|delta_Ev| > 0.05` eV) using the same Richardson-Dushman bound as 1D `continuity.py`. The `dn = +(div_x_n + div_y_n)/Q + G - R` sign for electrons (charge $-q$) and `dp = -(div_x_p + div_y_p)/Q + G - R` for holes are pinned by `tests/regression/test_twod_validation.py` — getting either sign wrong produces immediate Radau failure at V=0.

The Stage-A J-V driver `twod/experiments/jv_sweep_2d.run_jv_sweep_2d` bootstraps via 1D `solve_illuminated_ss` (or `solve_equilibrium` for dark) on the same y-grid, freezes the equilibrated ion profile via `P_ion_static_1d`, broadcasts $(n, p)$ to 2D, and walks the voltage grid with a per-step `run_transient_2d` settle (Radau-LU on the ~250×250 system at the test-grid sizes). The validation gate `tests/regression/test_twod_validation.py` runs the 1D and 2D solvers on the Beer-Lambert MAPbI3 preset with frozen ions and matched grids (1D `N_grid=31`, 2D `Ny_per_layer=10` × 3 electrical layers + 1 = 31) and asserts: $|V_{oc}^{2D} - V_{oc}^{1D}| \le 10^{-4}$ V, $|\Delta J_{sc}|/|J_{sc}| \le 5\times10^{-4}$, $|\Delta \text{FF}| \le 10^{-3}$, lateral invariance of $n$ at $V_{oc}$ to $\le 10^{-9}$, divergence of total electron+hole current bounded at interior nodes, and Poisson Dirichlet BCs match exactly. Final passing values: bit-identical 1D and 2D (`V_oc=910.634` mV, `J_sc=424.036` A/m², FF=0.8247).

Backend dispatch: `kind="jv_2d"` in `backend/main.py` accepts `lateral_length`, `Nx`, `Ny_per_layer`, `V_max`, `V_step`, `settle_t`, `illuminated`, `lateral_bc`, `save_snapshots` and serialises `JV2DResult` (V, J, grid_x in nm, grid_y in nm, lateral_bc, snapshots, **metrics**). `JV2DResult.metrics` is a `JVMetrics(V_oc, J_sc, FF, PCE, voc_bracketed)` populated centrally by `compute_metrics(voltages, J, assume_jsc_positive=False)` — same helper as the 1D side, so 2D and 1D metric definitions are bit-identical and the `voc_bracketed` flag has the same semantics on both. **2D Microstructure — Stage B (Phase 6 — Apr 2026).** Lateral grain boundaries with reduced SRH lifetimes, painted onto the absorber via `perovskite_sim/twod/microstructure.py`. The data model is two frozen dataclasses: `GrainBoundary(x_position, width, tau_n, tau_p, layer_role)` represents one vertical band, and `Microstructure(grain_boundaries=...)` is the container. `build_tau_field(grid, ustruct, tau_n_bulk_per_y, tau_p_bulk_per_y, layer_role_per_y)` extrudes the bulk $\tau$ along $x$ and then overrides cells inside each GB band where `|x - gb.x_position| < gb.width/2` AND the role tag at that $y$ matches `gb.layer_role`. Empty `Microstructure()` reduces to identity extrusion (Stage-A bit-identical). The YAML schema is a top-level `microstructure:` block with strict-key validation (`load_microstructure_from_yaml_block` raises `ValueError` on unknown keys so typos surface immediately):

```yaml
microstructure:
  grain_boundaries:
    - x_position: 250e-9   # m, GB centre
      width:      5e-9     # m, GB band width
      tau_n:      5e-8     # s, electron SRH lifetime inside GB
      tau_p:      5e-8     # s, hole SRH lifetime inside GB
      layer_role: absorber # only nodes tagged this role get overridden
```

`load_device_from_yaml` parses the block and stores the result on `DeviceStack.microstructure`. `run_jv_sweep_2d` accepts `microstructure: Microstructure | None = None`; when None it picks up `stack.microstructure` (then falls back to `Microstructure()`). Inside `build_material_arrays_2d` the role mask is derived by `_layer_role_at_each_y`, which assigns each $y$ node to exactly one electrical layer; layer-boundary rows are tagged with the upstream layer (HTL on the HTL/absorber interface, absorber on the absorber/ETL interface), so a single absorber GB touches the absorber/ETL interface row but not the HTL/absorber row. The shipped Stage-B preset `configs/twod/nip_MAPbI3_singleGB.yaml` (one centred GB, $\tau_\text{GB}=50$ ns vs $\tau_\text{bulk}=1$ µs, width 5 nm) drops $V_\text{oc}$ by ~46 mV vs the lateral-uniform baseline — pinned to a 5–100 mV regression window in `tests/regression/test_twod_microstructure.py`. Headline experiment: `voc_grain_sweep` (in `twod/experiments/voc_grain_sweep.py`) sweeps a sequence of grain sizes $L_g$, with one centred absorber GB per $L_g$ and periodic lateral BCs, and returns $V_\text{oc}(L_g)$, $J_\text{sc}(L_g)$, $\text{FF}(L_g)$ — exposed as `kind="voc_grain_sweep"` from the backend and as the **V<sub>oc</sub>(L_g) Grain Sweep** entry in the workstation. The `jv_2d` backend kind also accepts an optional `params.microstructure` block (same YAML shape) so users can add a single GB to a Stage-A run from the UI without editing YAML.

Stage-B scope boundaries — only $\tau$ heterogeneity is wired through; per-grain mobility, anisotropy, and dual-ion segregation across grains are deferred. The Stage-B physics gate uses Beer-Lambert presets to avoid the pre-existing 1D coupled-solver regression at V=0.21 V on TMM presets (`project_tmm_jv_regression_021.md`).

**2D Robin/selective contacts — Stage B(c.1) (Phase 6 — Apr 2026).** Ports the 1D Phase 3.3 Robin/selective-contact boundary condition to `assemble_rhs_2d`. When `SimulationMode.use_selective_contacts` is True and `DeviceStack` supplies any of `S_n_left`, `S_p_left`, `S_n_right`, `S_p_right`, `build_material_arrays_2d` sets `MaterialArrays2D.has_selective_contacts = True` and maps the four scalar S values via the 1D-transport-axis bridge:

```
DeviceStack.S_n_left  → MaterialArrays2D.S_n_top  (y=0,    HTL / p-contact)
DeviceStack.S_p_left  → MaterialArrays2D.S_p_top
DeviceStack.S_n_right → MaterialArrays2D.S_n_bot  (y=Ny-1, ETL / n-contact)
DeviceStack.S_p_right → MaterialArrays2D.S_p_bot
```

`continuity_rhs_2d` computes a one-sided Neumann y-divergence at the boundary rows (previously skipped). `assemble_rhs_2d` guards on `has_selective_contacts`: the `else` branch still zeros the four Dirichlet rows (Stage A/B(a) behaviour unchanged); the `if` branch calls `_apply_robin_contacts_2d` which subtracts the Robin wall flux from the Neumann base. The sign table (verified from first principles; `dp` signs are opposite to `dn` because `dp = −div_p/Q`):

```
dn[0,  :] -= J_n_top / (Q * hy_top)   # top electrons: J_n_top = +q·S·(n−n_eq)
dp[0,  :] += J_p_top / (Q * hy_top)   # top holes:     J_p_top = −q·S·(p−p_eq)  ← +=
dn[-1, :] += J_n_bot / (Q * hy_bot)   # bot electrons: J_n_bot = −q·S·(n−n_eq)
dp[-1, :] -= J_p_bot / (Q * hy_bot)   # bot holes:     J_p_bot = +q·S·(p−p_eq)  ← -=
```

Equilibrium densities use `mat.n_eq_left` / `mat.p_eq_left` for y=0 and `mat.n_eq_right` / `mat.p_eq_right` for y=Ny-1 (existing `(Nx,)` arrays; note the code comments on these fields had "top/bottom" reversed — fixed in this stage). The parity gate `tests/regression/test_twod_validation.py::test_twod_robin_parity_vs_1d` runs 1D Phase 3.3 vs 2D Stage B(c.1) on `configs/selective_contacts_demo.yaml` (frozen ions) and pins |ΔV<sub>oc</sub>| ≤ 1 mV — final passing values are bit-identical at the displayed precision (V<sub>oc</sub>=910.634 mV, J<sub>sc</sub>=424.036 A/m², FF=0.8247). The bounded-shift sanity test uses an aggressively-blocking Robin stack (`S_n_left=1e-4, S_p_left=1e-3, S_n_right=1e-3, S_p_right=1e-4` m/s — same envelope as 1D `test_selective_contacts_integration`) and asserts |ΔV<sub>oc</sub>| ∈ [1, 150] mV vs the Dirichlet baseline; the demo preset's matched S=1e3 m/s is effectively ohmic at this device thickness so the demo would not be useful for this assertion. `selective_contact_flux` was extended to accept array-valued `density_eq` so per-x equilibrium variation is supported when the build path eventually paints lateral structure into `n_eq_left/right`. Stage B(c.1) does not add Schottky barriers, per-column S patterning, or changes to the backend/frontend — those are out of scope.

**2D field-dependent mobility — Stage B(c.2) (Phase 6 — Apr 2026).** Ports the 1D Phase 3.2 μ(E) hook to `assemble_rhs_2d` using a **face-normal** formulation: x-faces use only `|E_x_face|`, y-faces use only `|E_y_face|`. When `SimulationMode.use_field_dependent_mobility` is True AND any layer sets a non-zero `v_sat_{n,p}` or `pf_gamma_{n,p}`, `build_material_arrays_2d` sets `MaterialArrays2D.has_field_mobility = True` and pre-computes 18 face arrays of `v_sat / ct_beta / pf_gamma` via **arithmetic mean** (interior x-faces, interior y-faces, periodic-x wrap face). On every RHS call, `assemble_rhs_2d` then calls `recompute_d_eff_2d` (in `perovskite_sim/twod/field_mobility_2d.py`) which: (1) computes `E_x_face = -(phi[:, 1:] - phi[:, :-1]) / dx[None, :]` and analogously `E_y_face` and the periodic wrap `E_x_wrap`; (2) forms base mobility `μ_base = harmonic_mean(D_node) / V_T` per face (Einstein); (3) applies the existing 1D `apply_field_mobility(μ_base, |E|, v_sat, beta, gamma_pf)` primitive face-normally — x-faces with `|E_x_face|`, y-faces with `|E_y_face|`. The primitive uses `np.abs(E)` internally so the input sign is irrelevant. (4) Recovers `D_eff = μ_eff · V_T` via Einstein. The effective per-face D is then forwarded through `continuity_rhs_2d` to `sg_fluxes_2d_n/p` via new keyword-only override kwargs (`D_n_x_face`, `D_n_y_face`, `D_p_x_face`, `D_p_y_face`, plus `D_n_wrap`/`D_p_wrap` for periodic). When the override is `None` (default) the harmonic-mean path runs unchanged → bit-identical to Stage A / B(a) / B(c.1). The `D_n` / `D_p` cache stays at the constant-mobility limit; only the per-face D injected into the flux helpers carries the field correction.

**Mean choice.** `D_n` / `D_p` continue to use harmonic mean (matches `sg_fluxes_2d_*` and 1D); `v_sat` / `ct_beta` / `pf_gamma` use arithmetic mean (avoids harmonic suppression at one-side-zero, which would silently disable CT/PF at heterointerfaces).

**2D self-consistent radiative reabsorption — Stage B(c.3) (Phase 6 — Apr 2026).** Ports the 1D Phase 3.1b reabsorption hook to `assemble_rhs_2d`. When `SimulationMode.use_radiative_reabsorption` is True AND `SimulationMode.use_photon_recycling` is True AND `MaterialArrays.has_radiative_reabsorption` is True (the 1D side has populated per-absorber tuples under TMM optics), `build_material_arrays_2d` translates `mat1d.absorber_masks` to 2D `absorber_y_ranges_2d` (each is a contiguous `(y_lo, y_hi)` half-open range derived from `layer_role_per_y == "absorber"`) and pre-computes `absorber_areas_2d = thickness × lateral_length` per absorber.

On every RHS call, `assemble_rhs_2d` calls `recompute_g_with_rad_2d` (in `perovskite_sim/twod/radiative_reabsorption_2d.py`) which: (1) for each absorber, computes `emission = B_rad[y_lo:y_hi, :] · n[y_lo:y_hi, :] · p[y_lo:y_hi, :]` of shape `(n_y_abs, Nx)`; (2) trapezoid in y first (axis=0) → `(Nx,)`; then trapezoid in x → scalar `R_tot_2D`; (3) skips if `R_tot_2D ≤ 0`, `area ≤ 0`, `P_esc ≥ 1`, or fewer than 2 nodes on either axis; (4) computes `G_rad = R_tot_2D · (1 − P_esc) / area`; (5) augments `G[y_lo:y_hi, :] += G_rad` (uniform redistribution over absorber 2D area). The cached `mat.G_optical` is **never mutated** — the helper returns a NEW `(Ny, Nx)` array. The augmented `G_to_use` is then forwarded to `continuity_rhs_2d`. When the flag is False, `G_to_use is mat.G_optical` (same Python object) — bit-identical to Stage A / B(a) / B(c.1) / B(c.2).

**Bit-equivalent to 1D in the lateral-uniform limit.** With constant `dx`, the lateral trapezoid evaluates to `lateral_length × emission_y(y)`, and dividing by `area = thickness × lateral_length` recovers `emission_y / thickness` — exactly 1D's `G_rad = R_tot · (1 − P_esc) / thickness`. The 2D y-range derives from `layer_role_per_y == "absorber"` (one half-cell narrower than the 1D inclusive mask at the HTL/absorber interface, which uses upstream-tagging in 2D); this trades ~1.3 mV V<sub>oc</sub> against the 5 mV B(c.3) parity envelope and keeps the absorber row semantics consistent with Stage B(a) microstructure painting.

**Lagged fallback in `jv_sweep_2d.run_jv_sweep_2d`.** Default per-RHS is fully self-consistent (Newton iters re-evaluate `R_tot_2D` from the live state). On `RuntimeError` from `run_transient_2d` AND `mat.has_radiative_reabsorption_2d` AND `illuminated`, `_bake_radiative_reabsorption_step_2d` evaluates `R_tot_2D` once at the entry state of the failed voltage step, folds `G_rad` into a step-local `G_optical` copy, clears the flag and zeros all four absorber tuples via `dataclasses.replace`, and retries `run_transient_2d` once with the baked `mat`. Across voltage steps the warm-start chain refreshes `R_tot` from the freshly-settled state, so the lag is bounded by `n·p` drift inside one settle interval. Mirrors 1D `experiments/jv_sweep.py:_bake_radiative_reabsorption_step` exactly.

**Activation gate.** `_has_rr_2d = sim_mode.use_radiative_reabsorption AND sim_mode.use_photon_recycling AND mat1d.has_radiative_reabsorption` — same tier-as-ceiling pattern established by Stage B(c.1) and B(c.2). LEGACY tier disables the hook even on TMM presets; FAST tier currently lists radiative reabsorption among the per-RHS hooks it skips, so FAST also stays on the disabled path. FULL enables when the preset supports it.

Pinned by the slow regression `test_twod_radiative_reabsorption_full_sweep_parity_vs_1d` which uses `settle_t=1e-5` and the `_integrate_step_2d` bisection-in-time path in `run_jv_sweep_2d`. ### Solver gotcha — RHS finite-check

`assemble_rhs` includes a `np.all(np.isfinite(dydt))` guard that raises `ValueError` if any element is NaN or Inf. This catches blow-ups from singular TMM matrices, zero-thickness layers, or extreme doping imbalances early — before Radau can silently accept them and produce garbage. Do not remove this check.

### Solver gotcha — Radau max_step cap

Near flat-band (V ≈ V<sub>bi</sub>) the Jacobian is nearly singular and Radau's adaptive LTE estimator under-reports the error, letting it accept one giant step on the wrong branch of the implicit system. This manifests as an unphysical J–V spike (e.g. `J=258` sandwiched between `188` and `101`). **All three experiments therefore cap `max_step = Δt / k`** on every `run_transient` sub-interval (`jv_sweep._integrate_step`, `impedance`, `degradation._measure_snapshot_metrics`). Do not remove these caps; if you need tighter control, lower the divisor instead. Any new experiment that calls `run_transient` across a voltage where the Jacobian can become near-singular must apply the same cap.

### Solver gotcha — wrong-branch rejection in the forward power quadrant (2026-07-28)

The `max_step = Δt/20` cap above is **necessary but not sufficient**, and it *cannot be made sufficient by tightening it*. Every recovery path in `_integrate_step` (bisection, the BDF fallback) is gated on `sol.success == False`; a Radau step that lands on the carrier-injection branch **succeeds**, so nothing fired and the bad value went straight into the J-V curve.

Measured on `ionmonger_benchmark` at `N_grid=40, n_points=20` — the shipped benchmark gate, whose V = 1.10526 sample sits essentially exactly on `V_bi` = 1.1 — the forward branch returned **J = 509.80 A/m² between neighbours 204.12 and 51.71**, giving FF = 2.13 and PCE = 56 % (both impossible: `P_mpp > V_oc·J_sc`) and HI = −1.74. Sweeping the divisor is **not** a fix and the attempt is recorded so it is not repeated: dt/20 → 509.8, dt/100 → 162.0, dt/200 → **255.9**, dt/1000 → 162.0, dt/2000 → 162.0. Non-monotone, because a global `max_step` change perturbs *every* step's trajectory and merely relocates which one lands wrong — the same lesson as the E9.3 clamp-shape variants.

What works is re-integrating **only the suspect step** and requiring subdivision convergence. At V=0 there is no universal lower photocurrent bound, so `_sweep` compares the original step with a 4-leg probe; a material disagreement is replaced only when a separate 8-leg solve agrees with the probe in both terminal current and every state block (`n`, `p`, `P`, optional `P_neg`, and interface state). This closes both tails measured at `n_points=15`: N=41 changes from 19.755 to 222.941 A/m², while N=55 changes from 467.554 to 223.004 A/m². For V>0, `_sweep` retains the protocol guard `J ≤ J_sc·(1 + _J_BRANCH_EXCESS)` (`_J_BRANCH_EXCESS = 0.05`) and tries the `2, 4, 8` ladder, but no longer accepts the first value that merely falls under the ceiling: two successive subdivisions must agree in current and state within 1 %. This distinction is load-bearing because the N=55 2-leg retry is 159.355 A/m² — below the ceiling but still the wrong branch — whereas 4/8 legs converge near 223 A/m². The absorbed-photon budget is a useful preset regression oracle, not a runtime ceiling on this transient total-current path: `_compute_current` also includes ionic and displacement current, so stored charge can exceed instantaneous optical generation.

**Why it reached `main`: the spike is BLAS-thread-dependent.** With the guard disabled, the same gate config gives `J(1.10526) = 161.986 / FF 0.79687` unpinned (12 threads) but `509.796 / FF 2.13233` pinned to one thread — different thread counts reassociate the LU reductions and perturb the Radau trajectory enough to flip which branch the near-singular step lands on. `tests/conftest.py` pins BLAS **only** when the `slow` marker is selected, so the `slow` lane saw the failure while a default `pytest` run was legitimately green. Any test targeting this class must pin BLAS itself rather than rely on the marker (`test_jv_branch_rejection.py` does, via a module-scoped autouse fixture, and is deliberately *not* `slow`-marked). Same sensitivity class as the `test_flat_band_contacts` note.

Two properties to preserve: a healthy V=0 probe is discarded, so its original state/current remain bit-identical; and a suspect result is replaced only after independent subdivision agreement. If a diagnostic/retry solve raises or the refinements do not converge, the successful single-leg state is retained and a `RuntimeWarning` tells the caller whether the point is unconfirmed or unconverged; one failed positive-bias leg does not prevent a later adjacent pair from recovering. The reverse sweep reaches V=0 only at its last point, so the same V=0 probe covers that datum; for positive reverse-bias points `run_jv_sweep` hands in the forward sweep's converged `J_sc` reference. Tests: `tests/unit/experiments/test_jv_branch_rejection.py`.

### Solver gotcha — BDF fallback after Radau bisection budget (May 2026)

`experiments/jv_sweep._integrate_step` halves `settle_t` on every `RuntimeError` up to `max_bisect = 10` (1024 sub-intervals). After that budget is exhausted, **before raising**, it retries once with `solve_ivp(method="BDF")` instead of Radau. BDF is more robust than Radau on near-singular Jacobians at the cost of slower per-step work; using it as the last-resort fallback eliminates the rare cases where Radau's adaptive LTE estimator stalls near flat-band. This path is hit only after the bisection budget exhausts, so the cost is bounded — but it converts otherwise-fatal sweep stalls into successful runs.

### Experiment gotcha — terminal-current measurement at SS (May 2026)

Suns-V<sub>oc</sub>, EQE, and any other experiment that pulls a single steady-state terminal current must use `experiments/jv_sweep._compute_current_ss(x, y, stack, V_app, mat=...)`, **not** `_total_current_faces(...)[0]` or `[N//2]`. The helper returns `np.median` across all interior faces of the per-face current. Charge conservation requires `J(x)` to be uniform at SS; in practice the boundary faces oscillate when ionic transients have not fully damped or when the Radau time-step has bottomed out at the bisection floor, and a single-face read picks up that boundary noise. The median is robust to a few outliers without requiring tighter convergence. Audit 2026-05-09 traced an `EQE_max = 48` artifact on `ionmonger_benchmark_tmm.yaml` (4881 % quantum yield) to terminal-face oscillation under a 1 ms settle; switching the sampler to median across faces was the single change that brought the slowest preset back to physical EQE ≤ 1.

### Experiment gotcha — slow ionic transients on TMM presets (May 2026)

The original `run_suns_voc` / `compute_eqe` defaulted to `t_settle = 1e-3 s` (1 ms). On TMM presets with `D_ion ≈ 1e-17 m²/s` (for example `ionmonger_benchmark_tmm`), that is only a carrier preconditioner; it does not define an ion-equilibrated history. An older note incorrectly evaluated `L²/D` for a 400 nm absorber as 16 ms: the value is about `1.6e4 s`. Faster screened/charging scales also coexist — about 0.2–1 s for the measured local relaxation and about 29 s for blocking-electrode charging on this preset — so there is no single 16 ms constant from which a universal settle can be chosen. **Defaults remain `t_settle = 1e-1 s` (100 ms)** because that empirical protocol, together with interior-face median sampling and a matched dark-`J(V=0)` subtraction, suppresses the measured residual enough on the shipped gates; it must not be described as full ionic equilibrium. EQE also uses `Phi_incident = 4e21` (1-sun integrated AM1.5G) so the monochromatic photo-signal dominates the remaining drift. A study of hysteresis or ion-equilibrated performance must specify its own pre-bias and dwell history rather than infer it from this default. Pinned by `tests/unit/experiments/test_eqe.py::test_eqe_in_unit_range_on_ionic_rich_preset` (`EQE ≤ 1.10` on the worst shipped preset).

### Experiment gotcha — the transient `run_jv_sweep` default `V_max` is blind to V<sub>oc</sub> (2026-07-26)

`_default_V_max = max(|V_bi|·1.3, 1.4)` is set by the **contact work functions** and knows nothing about the point being swept. On any device whose V<sub>oc</sub> collapses — deep cliff or spike band offsets, short lifetime, strong interface recombination — the sweep therefore grinds a long stretch of deep forward injection *above* V<sub>oc</sub>, which is the regime the steady-state notes above already flag as taking minutes per point. Measured on two spike-side screening points (|V_bi| = 0.791 → default V<sub>max</sub> 1.40, actual V<sub>oc</sub> ≈ 0.53): **1567 s and 630 s, versus 23 s and 16 s** when the range starts low and escalates only on a failed bracket — with V<sub>oc</sub> agreeing to 1.6 mV and 0.1 mV. That is pure wasted work, not a speed/accuracy trade.

It is also a **silent data-quality** hazard, not just a slow one. Under any per-point timeout the affected points are recorded as *failures*, and the failures are not missing at random: on a 256-point screening design 53 % of the chi ≥ 4.0 samples failed versus 2 % mid-range, so fitting a surrogate to the survivors would have imprinted a spurious cliff-vs-spike asymmetry. Switching protocol took the loss from 54/256 to 12/256, made it uniform across chi, cut wall clock 3767 s → 1298 s, and left the best point unchanged.

**Use the built-in ladder (2026-07-29).** `run_jv_sweep_ss` has `stop_after_voc=True` for the steady-state driver; the transient driver's equivalent is a **low `V_max` plus `v_max_max_attempts`** — start below every candidate and let it climb only where it must. That path now holds the first attempt's voltage step and grows `n_points` with each rung, so a retry no longer answers more coarsely than the attempt it corrects (it used to: 1.2/19 = 0.063 V → 1.7/19 = 0.089 V on the shipped fixture). It also stops once `V_max` saturates at `V_initial + 2.0` instead of re-running that sweep for the rest of the budget — the old bail-out compared a float with a `JVResult` and was dead code, measured at 10 sweeps for a 5-rung ladder.

Do **not** work around a range that misses V<sub>oc</sub> by holding `n_points` fixed and stretching it: that gives each point a different voltage step, the V<sub>oc</sub> interpolation error scales with the step, and where the affected points cluster on one side of a swept axis it fabricates an asymmetry in the result — which is exactly the failure above. The default `V_max` itself is deliberately unchanged; lowering it is a behaviour change for every caller and the pinned regression envelopes are anchored to it.

## Backend (`backend/main.py`)

Thin FastAPI wrapper. Two endpoint families:

**Legacy blocking endpoints** — `POST /api/jv`, `/api/impedance`, `/api/degradation`. Run synchronously and return the full result in one response. Kept for backwards compatibility; the frontend no longer uses them.

**Streaming job endpoints** (frontend uses these):
- `POST /api/jobs` — body `{kind, config_path|device, params}`. Dispatches the experiment onto a worker thread via `JobRegistry.submit` and returns `{job_id}`. The closure captured in `_run(reporter)` passes `reporter.report` as the `progress=` kwarg to the experiment.
- `GET /api/jobs/{id}/events` — Server-Sent-Events stream. Named events are `progress` (JSON `{stage, current, total, eta_s, message}`), `result` (final serialized result), `error` (on exception), and `done` (always last). The handler uses `run_in_executor` + a 0.5 s drain timeout to avoid blocking the event loop, and emits `: keepalive` SSE comments in the gap between progress frames.

For `kind="jv_2d"` and `kind="tandem_jv"` the `result` event additionally carries a `metrics` dict (`V_oc`, `J_sc`, `FF`, `PCE`, `voc_bracketed`) so the frontend can render the metric-card row without a second round-trip. The serialiser uses `from dataclasses import asdict` at the function scope; a bare `dataclasses.asdict(...)` reference inside the dispatch closure raises `NameError`. Regression tests consume the SSE stream end-to-end (`test_jv_2d_sse_result_event_carries_metrics_dict`, `test_tandem_sse.py`) — dispatch-only assertions cannot catch this class of scope bug because the `POST /api/jobs` response returns 200 even when the worker thread later crashes on result emission.

`backend/progress.py` and `backend/jobs.py` are the pub/sub primitive and the thread-per-job registry behind this. Any new experiment that wants progress should take a `progress: Callable[[str, int, int, str], None] | None = None` kwarg (see `experiments/jv_sweep.py` for the pattern) and the backend `_run` closure wraps it with `reporter.report`.

`GET /api/configs` auto-scans `configs/`, so dropping a new YAML in that folder makes it visible to the frontend with no code change.

**Solver selector + SCAPS physics flags from the UI (2026-06).** `POST /api/jv` and the `kind="jv"` job both accept `solver` (`"transient"` default = legacy Radau forward/reverse sweep; `"steady_state"` = ion-free Newton `experiments/steady_state.run_jv_sweep_ss`) plus `iface_states` (SS-only interface-plane carrier states). `backend/main.py:_run_jv_dispatch` routes between them and maps the SS driver's single hysteresis-free `JVSweepSSResult` into a `JVResult` with `V_fwd==V_rev` / `hysteresis_index=0.0` (the steady state has no hysteresis), so the frontend response contract is unchanged; the decompose/spatial kinds stay transient (they need the per-RHS snapshots/decomposition the SS Newton driver does not produce). Separately, `stack_from_dict` now plumbs the five device-level physics flags the YAML loader already parses — `dos_band_potentials`, `flat_band_contacts`, `interface_plane_closure`, `interface_plane_projection`, `het_recomb_despike` — via the `_flag` helper (was silently dropping them on the inline-`device:` path the frontend always uses); absent → off/0.0, bit-identical. Pinned by `tests/unit/backend/test_solver_dispatch.py`.

### Development loop — restart uvicorn after backend edits

`uvicorn backend.main:app --reload` picks up most edits, but the watcher is set on the SolarLab root and occasionally misses changes under `perovskite-sim/backend/`. If `/api/jobs` or a new endpoint returns 404 after an edit, kill and restart the process rather than trusting `--reload`.

### YAML scientific-notation gotcha

PyYAML's default loader is YAML 1.1, which only treats `1.0e-9` as a float — a bare `1e-9` (no decimal point) is returned as a **string**. The frontend's numeric editor then throws `v.toExponential is not a function` when rendering such a field. The fix lives in `backend/main.py:_coerce_numbers`, a recursive pass applied in `get_config` that turns any numeric-looking string into a float. When editing the backend do not bypass this coercion, and when adding new YAML configs you can use either form, but `1e-9` is fine because the backend normalises it.

### Backend URL: absolute, not proxied

`api.ts` and `job-stream.ts` both hardcode `http://127.0.0.1:8000` as the base URL. The Vite dev-server proxy is configured for `/api` in `vite.config.ts`, but its SPA history fallback intercepts `/api/configs` before the proxy has a chance to match, returning `index.html` — the JSON parse then fails with `Unexpected token '<'`. Hitting the backend directly sidesteps this. CORS is already wide open in `backend/main.py`, so this works from both `npm run dev` and `npm run preview`/`dist`.

SSE notes worth knowing:
- `EventSource` fires a native `error` event when the server closes the connection. `job-stream.ts:streamJobEvents` ignores events whose `e.data` is falsy — only SSE `event: error` frames sent from the backend are surfaced to the user.
- Progress frames and the terminal `done` frame go through named SSE events (`event: progress`, `event: result`, `event: error`, `event: done`), not the default message channel, so each has its own `addEventListener`.

### Streaming-job + progress-bar pattern

Each experiment panel (`panels/{jv,impedance,degradation}.ts`) follows the same shape:
1. Instantiate a `ProgressBarHandle` once in `mount*Panel` via `createProgressBar(progressContainer)`.
2. On button click, call `startJob(kind, device, params)` → get `job_id`.
3. Open the stream with `streamJobEvents<TResult>(jobId, { onProgress, onResult, onError, onDone })`.
4. `onResult` calls the panel-local `render*Results`; `onDone` re-enables the Run button.

The button is disabled between `startJob` and `onDone`, and the progress bar is `reset()` on every run so a second click doesn't briefly show the previous run's "done" state.

### Config gotcha — interface recombination is opt-in, silent when absent, and the YAML path is strictly weaker than the UI path

Three separate traps. The first two were measured on `solarscale_nip_band_aligned.yaml` (2026-07-26); the third is a 2D solver gap found 2026-07-29:

**1. The channel is opt-in, and absent on about half the presets.** Measured 2026-07-29 (the earlier "only 4 of 24" figure in this file was wrong): **14 of 27 loadable configs have a LIVE interface channel** — a non-zero `(v_n, v_p)` pair and/or a populated `InterfaceDefect` — and **0** carry the trap of a declared block whose velocities are all ≤ 0 (which F07 would silently reduce to `R = 0`). The 14 are `cSi_homojunction`, `cigs_baseline`, `cigs_graded_notch`, `driftfusion_benchmark{,_tmm}`, `driftfusion_calado2016_repro`, `ionmonger_benchmark{,_tmm}`, `ionmonger_courtier2019_repro`, `scaps_mirror`, `scaps_mirror_v2{,_robin_moderate,_robin_strong}`, `solarscale_nip_band_aligned_iface`.

On the 13 without it, `DeviceStack.interfaces == ()`, so band offsets reach **only** transport — the SG flux and the TE cap — and never the recombination channel. Most of those 13 are correct as shipped: `nip_MAPbI3` / `pin_MAPbI3` (+`_tmm`) are IonMonger-parity presets and IonMonger has no such channel; `radiative_limit` is deliberately ideal; `nip_SnPb_1p22` / `nip_wideGap_FACs_1p77` are tandem sub-cells; `field_mobility_demo` / `selective_contacts_demo` / `bcx_combined_demo` are banner-labelled feature demos; and the three 2D presets cannot use it at all (see the 2D gap below). **The one that is a genuine trap is `solarscale_nip_band_aligned`** — the band-alignment screening template — which is exactly why `solarscale_nip_band_aligned_iface` exists beside it. Use the `_iface` variant for any band-alignment study: sweeping the absorber `chi` over 3.5–4.2 eV moves V<sub>oc</sub> by **9.2 mV** with the block absent versus **294 mV** with a populated interface, so without it `chi` appears to move FF only and the alignment optimum reads as far more forgiving than it is.

The frontend does not flag the difference: `config-editor.ts:328` (and `:676` on the read path) render the "Interface Recombination (SRV)" panel from `config.device.interfaces?.[i] ?? [0, 0]`, so a config without the block shows the fields **pre-filled with zeros** rather than as unset.

**2. The defect, not the bare SRV, is the load-bearing half.** An `InterfaceDefect` does not merely supply different n1/p1 numbers — it activates the E<sub>t</sub>-aware cross-carrier evaluation path. Measured at tau = 1e-6, SRV = 0.1 m/s on both hetero-interfaces:

| | E<sub>g</sub> = 1.40, chi = 3.70 | E<sub>g</sub> = 1.60, chi = 3.70 |
|---|---|---|
| no `interfaces` | V<sub>oc</sub> 0.9017 | 1.0913 |
| `interfaces` only (all a plain YAML can express) | 0.8949 (**−6.8 mV**) | 1.0891 (**−2.2 mV**) |
| `interfaces` + `InterfaceDefect(E_t)` | 0.7585 (**−143 mV**) | 0.9436 (**−148 mV**) |

So the defect carries ~95 % of the effect. Do not compensate for a missing defect by inflating the bare SRV — it is a different, much weaker channel, and matching a number that way fabricates the agreement.

**3. 2D HAS the channel but it is OFF BY DEFAULT — corrected 2026-09-02 (TWOD-E1); the 2026-07-29 text below it said "cannot use it at all", which is now false.** `twod/interface_recombination_2d.py` implements a two-sided cross-node interface SRH sheet, selected by `build_material_arrays_2d(..., interface_srh="two_sided_cross_node")` and applied in `assemble_rhs_2d`; it **imports `interface_recombination` from the 1D `physics/recombination.py`**, so there is one rate law and two assemblies of it. It has its own registered lane (`twod-mobile-ion-interface-srh-v1`) and four test files.

What survives from the old warning is the **default**: `interface_srh` defaults to `"off"`, and the 2D builder accepts an interface-carrying stack without complaint, so a 2D run on a config that declares `device.interfaces` silently drops the channel. Measured at the interface node on a two-layer defect stack: `-4.49e24` (1D, and 2D with the channel on) versus `-5.0e-13` (2D default) — **24 orders of magnitude, silently**. The Stage-A gate cannot catch it because it runs on `nip_MAPbI3`, which declares no interfaces.

**Where the channel IS enabled, 1D and 2D agree EXACTLY** — relative difference `0.0` across six decades of carrier density including deep depletion, pinned by `tests/regression/test_twod_interface_srh_parity.py`. That is safe because 2D **fails closed on every configuration where the two formulations would diverge**, rather than approximating: 2D floors both SRH pairs unconditionally while 1D clamps pair A only when the escape hatch is unset AND a defect is declared AND the rate is negative, so 2D refuses a defect-free interface ("requires an InterfaceDefect") and refuses `SOLARLAB_IFACE_ALLOW_GEN=1` ("interface-generation escape hatch"). It also requires `lateral_bc="neumann"`, which is why no existing periodic parity baseline can be reused for the comparison.

Still genuinely absent from 2D: the QSS interface-plane closure and the SS interface-plane carrier states. See `docs/superpowers/plans/2026-07-29-2d-lateral-heterogeneity.md` Task 6.

**Both schemas now share one parser (2026-07-26).** `config_loader.interfaces_from_device_dict(dev, n_layers)` is the single source of truth for `device.interfaces` (legacy `[v_n, v_p]` pairs, m/s) **and** `device.interface_defects` (SCAPS-style `{sigma_n_cm2, sigma_p_cm2, v_th_cm_s, N_t_cm2, E_t_eV_below_cb, calibration_factor?} | None` per slot, SRV derived as `sigma·v_th·N_t`). Both `load_device_from_yaml` and `backend/main.py:stack_from_dict` call it, so a plain YAML can now express a trap level and the UI and file paths cannot drift — they had drifted repeatedly before, which is the same reason `material_params_from_dict` is shared. Where both schemas fill a slot the defect wins and the legacy pair survives only on `None` slots; absent keys still return `((), ())`, so every config that does not opt in is byte-identical. Tests: `tests/unit/models/test_config_loader_interface_defects.py` (includes a YAML-vs-inline parity case).

A calibration note for whoever populates these: an SRV set here is **device-level and grid-referenced**, not a face-value physical velocity. The cross-carrier interface SRH rate is sampled on bulk-interior nodes (over-counting relative to an interface-plane evaluation) and normalised by the interface dual-cell width, so it moves with `N_grid`. Measured on this stack, N_grid 60 → 120 shifts V<sub>oc</sub> by −16.0 mV on the cliff flank but only −0.6 mV at the alignment optimum and −0.6 mV on the spike flank — the residual is localised to the cliff side, not a uniform offset.

That caveat is executable, not just prose: `tests/regression/test_interface_srv_grid_reference.py` (slow) pins the calibrated penalty on `solarscale_nip_band_aligned_iface` at its own mesh (−188.0 mV ± 10) and asserts the contrast that defines "grid-referenced" — at fixed voltage resolution, N_grid 60 → 120 leaves the interface-**free** config at −0.2 mV (converged) and moves the interface-active one by −11.8 mV, so essentially all of the mesh sensitivity is the interface channel. If that second assertion ever fails because the channel became mesh-independent, this note is stale: delete it and the test together.

**What the SRV does NOT control is the band-alignment optimum.** Both interfaces carrying the same velocity is an assumption, and it could in principle be what produces the tilted acceptance band Stage 2c reports — so it was tested by breaking the symmetry. At Eg = 1.40, tau = 1e-6, making one interface 10× more recombination-active than the other moves the optimum chi by −0.029 eV (HTL loaded) or +0.048 eV (ETL loaded), against a ridge drift of 0.164 eV across the accepted Eg span: under a third of the effect, and in the expected direction each time (the optimum moves *away* from the loaded interface). Absolute efficiency does depend on the SRV (19.03 % symmetric, ~18.6 % imbalanced) — geometry is robust, absolutes are conditioned. Pinned, magnitude and sign separately, by `tests/regression/test_interface_balance_ridge.py` (slow).

## Data Model Invariants

- `MaterialParams`, `SolverConfig`, `LayerSpec`, `DeviceStack` are **frozen dataclasses**. Never mutate in place — use `dataclasses.replace(...)` to produce a new instance (see `degradation._freeze_ions` for the canonical pattern).
- All physical quantities are SI (m, s, V, A/m², m⁻³). The only exceptions are `chi` and `Eg` which are in eV (numerically equal to volts through `q`).
- `DeviceStack.interfaces` is a tuple of `(v_n, v_p)` pairs with length `len(layers) - 1`, ordered from contact side to contact side.

## Test Structure

`tests/unit/` holds per-module physics/solver/experiment tests, `tests/integration/` end-to-end runs on preset configs, and `tests/regression/` physical sanity checks (V_oc range, J_sc bounds, ...).

`pytest` defaults (from `pyproject.toml`) exclude `-m slow`. Coverage is **opt-in** — pass `--cov=perovskite_sim --cov-report=term-missing` explicitly when you want a report. The regression suite is where to add new "result should look physically reasonable" checks.

Regression tests:
- `test_jv_regression.py` — V<sub>oc</sub> / J<sub>sc</sub> / FF / HI envelopes for all presets
- `test_tmm_baseline.py` — TMM-specific baselines (slow, BLAS-pinned)
- `test_conservation.py` — energy conservation (R+T+A=1) and J-V monotonicity checks; catches TMM numerical issues and solver blow-ups

### Measurement gotcha — hand-written probe scripts get NO BLAS pinning

The pinning below lives in `tests/conftest.py`, so it only protects code run **through pytest**. A hand-written probe — `python3 - <<EOF`, a `scripts/` one-off, anything driving `solve_voc_ss` / `run_jv_sweep` / `build_material_arrays` directly — bypasses it entirely and inherits the OpenBLAS default of one thread per core.

Measured 2026-07-27: a bare `python3` probe running `solve_voc_ss` on `scaps_mirror_v2` sat at **934 % CPU for 30 minutes without producing a result**, while a concurrent BLAS-pinned `pytest -m slow` on the same box was starved to **76 % of a single core**. Killing the probe returned the pytest run to 100 % immediately. The probe was not merely slow — it was ~9 cores of pure thread-thrash on matrices too small to parallelise, and it corrupted the wall-clock reading of the measurement it was competing with (an agent in the same session retracted a 314 s timing for exactly this reason).

So: **pin threads in every probe script**, with the same ordering constraint the conftest hook documents — `threadpool_limits` only sees BLAS backends that are **already loaded**, so numpy (and `scipy.linalg`, which registers a second BLAS on some builds) must be imported *first*. Calling it at the very top of the file, before those imports, is a **silent no-op** — the trap this note exists to prevent:

```python
import numpy, scipy.linalg                 # MUST come first — registers the BLAS
from threadpoolctl import threadpool_limits

with threadpool_limits(limits=1, user_api="blas"):
    ...                                    # every solver call goes inside
```

The env-var route (`OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1` in the invoking shell) has no ordering constraint and is the safer choice for a throwaway `python3 - <<EOF` probe.

Numerical results are unaffected either way — this costs only wall-clock — but an unpinned probe makes every concurrent timing on the machine untrustworthy, and looks like a hang.

### Test gotcha — slow suite BLAS thread pinning

The TMM regression suite (`tests/regression/test_tmm_baseline.py`) drives ~4700 calls to `scipy.linalg.lu_factor` on the ~300×300 Radau Jacobian. These matrices are too small for multi-threaded BLAS to pay off — on a 10-core box OpenBLAS spins up every LU call across all cores and the thread-creation + contention overhead turns a 14 s test into a 5-10 minute test. A Phase 2a investigation wasted four run-kills diagnosing this as a "stall" (runs were being terminated at ~4 min wall, but they would have taken another 2-3 min each to finish under oversubscription). It is NOT a hang.

`tests/conftest.py` pins BLAS threads to 1 via `threadpoolctl` whenever the `slow` marker is selected (excluding the default `-m 'not slow'` unit run). numpy/scipy must be imported inside the hook before calling `threadpool_limits`, because threadpoolctl only sees already-loaded backends. Do not remove this hook; also do not re-bake `--cov=perovskite_sim` into `pyproject.toml` `addopts` — pytest-cov's line tracer adds a further ~17× overhead on the same hot loop and is equally sticky (the tracer is installed during pytest-cov's own `pytest_configure`, before any user conftest gets a chance to stop it).

Canonical invocations (wall clock measured 2026-07-29 on a 10-core Darwin box):
- Unit + integration: `pytest` (default, no coverage) — **1350 passed / 2 skipped in 1 min 55 s**. Re-measured 2026-08-13 at `dab5b98`: **1694 passed / 2 skipped in 2 min 19 s** (258 deselected).
- Unit with coverage: `pytest --cov=perovskite_sim --cov-report=term-missing`
- Slow regression: `pytest -m slow` (BLAS pinned automatically) — 213 tests. The "~27 s" that used to appear here referred only to `test_tmm_baseline.py`, not the lane; budget over an hour. Re-measured 2026-08-13 at `dab5b98` on a clean local-disk clone: **258 selected, 254 passed / 4 skipped in 2 h 01 min 14 s** — "over an hour" now under-budgets it by 2×. Two items are 29 % of the lane: `test_physical_interface_cbo_scan::test_two_sided_fd_adaptive_full_jv_covers_physical_solver_path` (1256 s, nearly all in `setup`) and `test_twod_validation::test_twod_radiative_reabsorption_full_sweep_parity_vs_1d` (847 s). Five `tests/integration/test_autoloop_*` cases add ~1300 s more. Do not time either lane on the OneDrive mount — see the placeholder-hydration note below.
- Literature validation: `pytest -m validation` (paper-config + physical-trend gates; also `slow`-marked — ~12 FULL-tier sweeps each, minutes — so the default `pytest` excludes them)

**Keep the default lane under ~2 minutes: if a test runs a full sweep, mark it `slow`.** The marker had eroded to the point where the default lane took **16 min 58 s** (documented as "~15 s", stale by ~68×), because 23 of the 25 files under `tests/unit/` that drive a full `run_jv_sweep` / `run_transient` / `solve_voc_ss` carried no marker, plus 15 more under `tests/integration/`. Collection is 1.4 s, so this was always execution cost, not imports. Re-marked 2026-07-29 at a 3 s per-test threshold — over ~3 s a test is doing a real solve rather than a unit assertion — moving 213 tests into the slow lane and taking the default lane to **1 min 55 s (8.8×)**.

**The trap when you do this again: a shared module-scoped fixture is charged to whichever test happens to run FIRST.** Marking that one test does not remove its cost — it silently moves it to a sibling that stayed behind. The first pass here marked 73 functions by measured duration and still left 4 min 10 s, of which 135 s was pure `setup` in five files (`test_e1_interface_srh`, `test_voc_collapsed_current`, `test_mott_schottky`, `test_e1_5_cross_carrier_srh`, `test_scaps_mirror_cbo_trend`) that each build a module-scoped device sweep. The fix is to mark **every test that requests the expensive fixture** (transitively — fixtures request fixtures), not just the profiled one. Do *not* reach for marking the whole file: in `test_voc_collapsed_current.py` only 3 of 23 tests touch the costly fixture, and in `test_mott_schottky.py` only 4 of 8, so file-level marking would drop 24 genuinely fast assertions out of the fast lane.

**Deliberate carve-out — do not mark it.** `tests/unit/experiments/test_jv_branch_rejection.py` stays in the default lane (~25 s across four tests) and pins BLAS itself via a module-scoped autouse fixture, because the wrong-branch spike it guards is BLAS-thread-dependent and must be caught without `-m slow`. It is now the single largest item in the fast lane, and that is a deliberate purchase.

**Run the suites from a local-disk clone, not from the OneDrive mount.** Measured 2026-08-13: 8378 of 10526 loose objects in `.git` (79.6 %, 192.73 MiB) were dataless OneDrive placeholders — `st_size > 0` but `st_blocks == 0`. `reproducibility.py::_dataless_loose_object` detects exactly this and fails `tests/reproducibility/test_matrix.py::test_p0_patch_and_frozen_files_match_manifest` closed with "Git object is a dataless OneDrive placeholder"; that failure is environmental, and the same test passes in a clean clone. Hydrating by reading the objects sequentially measured **1.2 objects/s, 30 KiB/s** (~116 min for the remainder) because File Provider round-trips per file and the object store is tens of thousands of tiny files — cost scales with object *count*, not bytes, and parallel reads are what crashed File Provider before, so it cannot be sped up safely. A fresh `git clone` from GitHub takes **36 s** for the whole repo (9181 objects, one pack, zero dataless) — ~200× faster. The same mount also stalled a bare `pytest` collection for over 6 minutes at 0.0 % CPU (pure I/O block) before the tree was hydrated.
